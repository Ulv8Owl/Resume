# Автотесты рекламных воронок

Playwright + TypeScript. Тесты проходят воронку как реальный пользователь на iPhone и Android, перехватывают аналитику PostHog и сверяют всё с конфигом воронки. **Реальная оплата не совершается:** экраны после оплаты открываются через `?step=n`.

## Что проверяется

| Проверка | Как | Какой баг ловит |
|---|---|---|
| A/B из `?metadata` | Эксперимент, рукава и проценты сверяются с конфигом, сумма процентов = 100 | Рукав выключили или забыли, проценты сломаны |
| Метадата не изменилась | Снапшот текста `?metadata` | Тихо сменили продукт, цену, сплит |
| Рукава реально разные | Каждая ссылка на рукав открывается, первые экраны сравниваются | Параметр `variant` игнорируется |
| Реальное распределение | N заходов «новыми пользователями», подсчёт рукавов (`DIST_SAMPLES`) | Весь трафик уходит в один рукав |
| Путь до оплаты | Клики по вводным экранам, ввод username, анимация анализа, пейвол; плюс путь через «Пропустить» — в каждом рукаве | Сломанные переходы, неверная цена на пейволе |
| Аналитика PostHog | Перехват и распаковка (gzip/base64) событий | Нет событий, дубли, смена `distinct_id`, события без рукава или с чужим рукавом |
| Пейвол | Цены `$1` / `$49.99`, загрузка формы Solidgate | Неверная цена, форма оплаты не загрузилась |
| Аппселлы | Вводные экраны → предложение; «Пропустить» на **каждом** вводном экране → предложение того же продукта; «Нет, спасибо» → следующий аппсел | «Пропустить» уводит не туда, сломан отказ |
| Экран доступа | Нет повторных предложений купить основной продукт и аппселлы | Повторная продажа уже купленного |
| Здоровье страницы | JS-ошибки, ошибки консоли, ответы 4xx/5xx | Падения скриптов, битые ресурсы |

К каждому тесту в отчёте прикладываются скриншоты всех шагов, лог событий аналитики (`analytics-events.json`), а при падении — видео и trace.

## Запуск

```bash
npm install
npx playwright install chromium

npm run discover   # 1. Обходит ?step=1..40 и находит номера пейвола, аппселлов и экрана доступа
npm run baseline   # 2. Сохраняет эталон метадаты (повторять, когда метадату меняют намеренно)
npm test           # 3. Все проверки
npm run report     # HTML-отчёт со скриншотами
```

Полезные переменные:

- `FUNNEL=claude-tour npm test` — прогнать одну воронку.
- `DIST_SAMPLES=60 npm test` — включить проверку реального распределения трафика по рукавам. Допуск задаётся в `DIST_TOLERANCE`, по умолчанию 20 п.п.
- `BASE_URL=https://staging...` — другой домен.

`npm run discover` сохраняет в `.discovered/<домен>/` JSON и таблицу `claude-tour.md` со всеми экранами, ценами и кнопками. Это готовая карта воронки, её стоит закоммитить.

## Как добавить новую воронку

1. Скопировать `funnels/claude-tour.ts` и поменять путь, эксперимент, продукты, цены и тексты кнопок.
2. Зарегистрировать воронку в `funnels/index.ts`.
3. Запустить `npm run discover && npm run baseline && npm test`.

Если в воронке нет A/B, поле `experiment` не указывается: тогда тест проверяет, что в метадате нет рукавов, а путь проходится один раз.

## Самопроверка: тесты ловят реальные баги

В `mock/` лежит копия флоу claude-tour с `?metadata`, `?step=n`, рукавами и событиями PostHog в gzip. Тесты прогоняются на ней:

```bash
npm run selftest                       # чистая воронка — все тесты зелёные
MOCK_BUG=wrong-price npm run selftest  # намеренный баг — тесты должны упасть
```

| `MOCK_BUG` | Баг | Какой тест падает |
|---|---|---|
| `wrong-price` | $59.99 вместо $49.99 на пейволе | путь до оплаты, пейвол, снапшот |
| `dup-event` | событие отправляется дважды | «Дубли событий» |
| `ignore-variant` | параметр рукава игнорируется | «рукава реально разные», «чужой рукав в событиях» |
| `untagged` | события без пометки рукава | «Ни одно событие не помечено рукавом» |
| `skip-broken` | «Пропустить» в аппселле 1 ведёт в аппселл 2 | «Пропустить на каждом вводном экране» |
| `reoffer-main` | на экране доступа снова продают основной продукт | «экран доступа» |
| `meta-percent` | проценты рукавов в сумме 90 | «сумма процентов», снапшот |
| `js-error` | JS-ошибка на экране результатов | «JS-ошибки на странице» |

## CI

`.github/workflows/funnel-tests.yml` запускается по расписанию каждое утро и вручную (можно указать воронку). Сначала идёт самопроверка на моке, потом прогон боевых воронок. HTML-отчёт сохраняется как артефакт.

## Что нельзя проверить без оплаты

- Recovery-экран после отмены Apple Pay: его можно открыть через `?step`, но саму отмену нельзя.
- Что после успешной оплаты переход происходит только после успеха.
- Что подписка в Solidgate создаётся с правильным product_id. В метадате есть только названия продуктов, поэтому сверяются названия и цены на экранах.

Для этого нужна песочница Solidgate с тестовыми картами: это следующий шаг.
