# Академия QA — тренажёр к собеседованию тестировщика

Веб-приложение без сборки: открой `index.html` в браузере (нужен интернет: SQLite грузится с jsDelivr, прогресс — в Supabase).

Тебя встречает аватар мага твоего звания, звание с именем и башня с десятью режимами. Опыт общий для всех режимов:
чтобы стать Архимагом, нужно пройти почти всё во всех режимах. Шестерёнка в шапке открывает настройки:
вход, выход из аккаунта и сброс прогресса.

| Режим (комната в башне) | Доля опыта | Что внутри |
|---|---|---|
| Теория (библиотека) | 12% | 160 вопросов собеседования: 16 тем по 10 карточек, с примерами и словариком |
| SQL (подземелье) | 24% | Подземелье запросов: 90 залов от `SELECT` до процедур, подсказки при вводе |
| Тест-дизайн (совет магов) | 7% | 20 задач-конструкторов: классы эквивалентности, границы, таблицы решений, переходы, pairwise |
| API · Swagger (башня свитков) | 9% | 20 уровней: параметры, авторизация, схемы, границы, PUT/PATCH, пагинация, коды ошибок |
| API · Postman (почтовая башня) | 10% | 20 уровней: переменные, авторизация, тесты `pm.test`, цепочки, Runner, data-driven |
| API · Charles Proxy (хрустальный шар) | 8% | 20 уровней: прокси и сертификат, SSL Proxying, Breakpoints, Map Local/Remote, Rewrite |
| DevTools (обсерватория) | 9% | 20 уровней: Console, Network, Elements, Application, Device Toolbar, Sources |
| Git · GitLab CI (цитадель) | 8% | 20 уровней: терминал git, merge request, конфликты, пайплайны, `.gitlab-ci.yml` |
| Нагрузка · JMeter (мастерская голема) | 8% | 20 уровней: Thread Group, слушатели, ассерты, корреляция, точка насыщения, soak, non-GUI |
| Поиск работы (воронятня) | 5% | Бесконечные задания: Telegram, Хабр Карьера, HeadHunter, LinkedIn, другие сайты, компании |

Главное меню — башня Академии (`Avatars/Town.jpeg`): каждая комната открывает свой режим.
Наставник (`Avatars/Teacher.jpeg`) каждый день даёт задание: 20 карточек теории, 10 залов SQL и два случайных дела;
за выполнение — 200 золота и видео. С ним можно поговорить: о задании, о том, чем заняться дальше, о собеседованиях.

В симуляторах уровни открываются по порядку: следующий — после прохождения предыдущего.

## Звания и опыт

- 8 званий от Ученика до Архимага, у каждого свой аватар (`Avatars/1.webp` … `8.webp`).
- Весь опыт игры — 20 000 XP. Архимаг — на 92% всего опыта: под конец полного прохождения игрок успевает им побыть.
- Опыт не хранится, а считается из пройденного (`progression.js`). Подсказки уменьшают только золото и звёзды.

## Поиск работы

Реальные действия при поиске работы: отправил резюме рекрутёру, откликнулся, опубликовал резюме в канале,
добавил канал или компанию. Задания бесконечные: за каждое — золото и опыт. Цель дня (5 откликов или резюме) даёт
бонус, считается серия дней подряд, последнее действие можно отменить. В «Компаниях» — список компаний со ссылками
на их QA-вакансии и статусом (отклик, собеседование, оффер, отказ). Опыт копится без конца,
но в звание засчитывается не больше 5% всего опыта игры.

## Видео-награды

- Видео лежат только на твоём компьютере, в папке `mp3/` рядом с `index.html`. Папка в `.gitignore`:
  в git и в Supabase видео не попадают, в прогрессе хранятся только номера полученных видео,
  число воспроизведений и избранное.
- **Зашифрованные видео** (открываются только в игре): оригиналы лежат в папке, доступной только root,
  и один раз шифруются в папку игры: `sudo bash tools/encrypt-videos.sh /путь/к/оригиналам ./mp3`.
  Получаются `check.js` и `1.js` … `144.js` (AES-256, ключ из пароля); открыть их напрямую нельзя.
  При первом просмотре игра спрашивает пароль, расшифровывает видео в памяти и играет его оттуда.
  Пароль можно запомнить в браузере, а кнопка «🔒 Заблокировать» в инвентаре его забывает.
- Можно и без шифрования: обычные файлы `1.mp3` … `144.mp3` (подходят `.mp4` / `.webm`) — если в папке нет `check.js`.
- Где выпадает видео (всегда случайный файл из тех, которых ещё нет в инвентаре):
  - SQL — каждый третий зал (3, 6 … 90) при первой победе;
  - режимы по 20 уровней (Тест-дизайн, Swagger, Postman, Charles, DevTools, Git) — уровни 4, 7, 10, 13, 16, 19;
  - Теория — с шансом 10% за каждый ответ «Знаю», который засчитан;
  - Поиск работы — с шансом 10% за каждое «Сделал» (если действие отменить, видео тоже забирается).
  Уровни и залы с наградой отмечены 🎬.
- В окне награды — большая иконка 🎬: нажми, чтобы посмотреть сразу. Закрыл окно, не посмотрев, —
  одно бесплатное воспроизведение ждёт в инвентаре (🎒 в шапке).
- В инвентаре у каждого видео превью и счётчик воспроизведений; без воспроизведений превью чёрно-белое.
  «＋» покупает одно воспроизведение за 50 золота. ☆ добавляет видео в избранное, вкладка «★ Избранное» показывает только их.
- Одно воспроизведение ≈ 25–30 секунд: короткое видео повторяется (15,2 с → 2 раза, 5 с → 5 раз),
  длинное играет один раз целиком.
- Настройки (папка, число файлов, уровни с наградой, шанс, цена, длительность) — в начале `rewards.js`.

## Теория

16 тем по 10 карточек. Вопрос → можно открыть до трёх свитков подсказок → «Знаю» или «Не знаю».
- «Знаю»: карточка переворачивается, и ты честно отмечаешь, какие ключевые пункты назвал. Половина и больше — засчитано.
- «Не знаю»: читаешь ответ, карточка вернётся в колоду через три вопроса.
- Серия верных ответов подряд увеличивает золото. Мастерство карточки растёт с каждым повторением пройденной темы.

## Вход и сохранение в Supabase

- При первом заходе открывается экран **Вход / Регистрация**. Регистрация — только никнейм и пароль, без почты и подтверждений.
- Никнейм уникален без учёта регистра (`Aers` и `aers` — одно имя). Пока вводишь его, форма проверяет, свободен ли он.
  Правила: 2–32 символа, латиница, кириллица, цифры, пробел, `-` и `_`. Пароль — от 6 до 72 символов.
- После входа сессию хранит и продлевает библиотека `supabase-js`, поэтому при следующих заходах игра входит сама.
  Если сессия пропала или ты вышел, снова откроется экран входа с подставленным никнеймом.
- Можно играть без аккаунта: прогресс останется только в этом браузере, а войти можно позже с главного экрана.

Как это устроено в Supabase:
- Каждый маг — пользователь **Supabase Auth** (Authentication → Users), никнейм виден в колонке Display name.
  Почта для Auth служебная (`u<id>@players.qa-academy.app`): она генерируется из id и нигде не используется,
  а пользователь создаётся уже подтверждённым — поэтому писем и подтверждений нет, и настройка Confirm email не важна.
- Регистрацию выполняет функция `qa_register`: проверяет никнейм, создаёт пользователя Auth и строку прогресса.
  Вход: `qa_login_email` находит служебную почту по никнейму, а пароль проверяет сам Supabase Auth.
- Прогресс лежит в таблице `qa_progress` (Table Editor). RLS: игрок читает и меняет только свою строку и только поле `state`.
- Вся схема — один файл `supabase/migrations/20261011_qa_academy.sql`. Его можно запускать в SQL Editor
  сколько угодно раз: он ничего не удаляет, а испорченные функции возвращает к правильным версиям.
- Разовая очистка старых таблиц — `supabase/cleanup-legacy.sql` (уже не нужна, если её однажды запускали).

## SQL · Подземелье запросов

### Как играть

Ты — маг в подземелье. Монстры хотят тебя убить, а сила твоих заклинаний — в Хрониках (это база данных):
что прочитано в Хрониках, даёт знание, а что записано в них, становится явью. SQL-запрос — это заклинание.

1. Выбери зал на карте. 90 залов в трёх актах, в каждом акте по 30 залов, боссы в каждом десятом зале.
2. Прочитай задание и посмотри схему БД. Клик по таблице показывает её строки.
3. **Разведать** — бесплатно выполнить заклинание и посмотреть результат. Хроники после разведки восстанавливаются.
4. **Атаковать** — сдать заклинание на проверку.

Книга заклинаний в каждом зале открывается пустой: запрос пишется с нуля.

| Акт | Залы | Темы |
|---|---|---|
| I · Верхние ярусы | 1–30 | `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`, `INSERT`, `UPDATE`, `DELETE` |
| II · Глубины | 31–60 | агрегаты и `GROUP BY`/`HAVING`, `JOIN` всех видов, подзапросы, `CASE` |
| III · Бездна | 61–90 | индексы и `EXPLAIN QUERY PLAN`, транзакции, представления, триггеры, процедуры |

В SQLite нет `CREATE PROCEDURE`, поэтому в третьем акте процедуры собираются так, как это делают на практике в SQLite:
представление служит «входом», а триггер `INSTEAD OF INSERT` — телом процедуры.

## Как проверяется заклинание

- **Запросы** сравниваются с эталоном по колонкам и строкам (и порядку, если он важен).
  Урон монстру пропорционален тому, насколько результат близок к ответу.
- **Изменения** (`INSERT`/`UPDATE`/`DELETE`, транзакции) сравниваются по тому, *что изменилось* в Хрониках:
  ничего не сделать — ноль урона, лишние изменения снижают урон.
- **Оптимизация** проверяется по настоящему плану запроса: `EXPLAIN QUERY PLAN` должен показать поиск по индексу.
- **Представления и триггеры** проходят испытание: после заклинания Хроники выполняют свои команды и смотрят на результат.
- Незафиксированная транзакция отменяется, как при обрыве соединения.

## Награды и звания

- Неверная атака — монстр контратакует. Ошибка SQL — урон вдвое меньше.
- Здоровье кончилось — возврат в лагерь, монстр восстанавливается, теряется 25% золота.
- Три свитка подсказок открываются по одному и уменьшают золото за зал: 100% → 70% → 40% → 20%, каждый снимает звезду.
- Победа без ран — +25% золота.
- Опыт за зал фиксирован и от подсказок не зависит. 8 званий: Ученик → Подмастерье → Адепт → Чародей → Волшебник →
  Магистр → Верховный магистр → **Архимаг**. Пороги посчитаны так, что звание Архимага даёт победа над последним, 90-м монстром.
  Каждое звание добавляет 20 к максимуму здоровья.
- Прогресс хранится в `localStorage`.

## Пентаграмма

Пока пишешь запрос, ключевые слова превращаются в руны на круге. Первая вершина — «глагол» заклинания:
Призыв (`SELECT`), Сотворение (`INSERT`), Преображение (`UPDATE`), Изгнание (`DELETE`), Возведение (`CREATE`).
Остальные вершины — `FROM`/`INTO`/`SET`, `WHERE`, `GROUP BY`, `ORDER BY`. Малые руны между ними —
`JOIN`, `HAVING`, агрегаты, транзакции, индексы, представления, триггеры, подзапросы и другие.
Круг светится зелёным, если запрос компилируется, и красным, если в нём ошибка.

## Файлы

- `progression.js` — режимы, бюджет опыта, звания.
- `core.js` — общее состояние, сохранение (браузер + Supabase), шапка, стартовый экран.
- `theory-data.js`, `theory-cards/`, `theory.js` — режим «Теория»: темы, карточки по темам и сам режим.
- `sims/` — имитация API-сервера (`api-mock.js`), общая панель испытания (`quest.js`) и пять симуляторов со своими стилями.

- `data.js` — схема и данные Хроник, раскладка ER-диаграммы, звания, акты, расчёт силы монстров и наград.
- `rooms-act1.js`, `rooms-act2.js`, `rooms-act3.js` — залы: задание, эталон, подсказки, способ проверки.
- `judge.js` — судья: выполняет заклинание и сравнивает с эталоном. Один и тот же код работает в браузере и в тестах.
- `app.js` — игра: бой, награды, звания, рендер.
- `spell.js` — пентаграмма.
- `tests/check-rooms.js` — проверка всех залов.

## Проверка залов

```bash
npm i sql.js@1.10.3
node sql-trainer/tests/check-rooms.js
```

Для каждого зала тест проверяет, что эталон побеждает, пустые и типичные ошибочные заклинания не побеждают,
альтернативные верные решения из `tests/cases.js` побеждают, готовая третья подсказка побеждает,
а последний зал даёт звание Архимага.
